# 威胁模型与边界

## 目标

本项目用于在用户自己的 iPhone/iPad 上，通过 Shadowrocket 拦截已被明确列入清单的广告、诈骗和博彩域名，并把顶层网页导航重定向到统一提示页。

## 不做什么

- 不分析网页正文，也不使用 AI 实时判定网站性质。
- 不窃取、记录或上传用户的完整访问 URL。
- 不修改未列入清单的域名流量。
- 不保证拦截原生 App 内的所有嵌入广告请求。
- 不替代浏览器安全浏览、系统反欺诈或上游 DNS 安全服务。

## HTTPS 与 MITM

HTTPS 重写依赖 Shadowrocket 的本地中间人解密功能。用户必须主动安装并信任 Shadowrocket CA 证书。证书具有较高权限，应仅安装在用户本人控制的设备上，不应导出或分发私钥。

模组只把网页跳转清单和 Google/YouTube 清理功能所需的精确主机加入 MITM hostname，
不对 `google.com`、`youtube.com` 或 `googlevideo.com` 使用根域通配符。
由于正常帖子加载兼容问题，正式模组不再加入 `x.com`、`twitter.com`、
`api.x.com` 或 `api.twitter.com`，也不执行 X 响应脚本。
`block.rainyxin.cyou` 被生成器硬性排除，防止循环拦截。

## 隐私

重定向请求只向服务器发送：

- `category`：`ads`、`scam` 或 `gambling`
- `source`：固定值 `shadowrocket`

原始目标放在 `#target=` URL 片段中。浏览器不会把片段发送给服务器，页面脚本只在本地解析它，用于展示目标主机名和实现二次确认后的继续访问。页面不包含分析、广告、第三方字体或其他外部资源。

继续访问逻辑只接受 `http` 和 `https`，并拒绝指向拦截页自身的目标。由于 Shadowrocket 重写发生在网络层，原始 URL 的客户端片段无法恢复。

## 博彩类别

博彩类别会在短暂提示后跳转到浙江省互联网违法和不良信息举报中心的匿名举报页。该入口由浙江互联网信息办公室主办，并明确提供“赌博类”危害类型。

## 广告资源的限制

广告联盟域名通常作为脚本、像素或推荐组件嵌入其他网站。拦截这些子资源可以阻止其加载，但浏览器不一定会把整个顶层页面导航到拦截页。域名清单必须保持保守，避免加入同时承载登录、支付或核心静态资源的宽泛根域名。

Google 搜索广告与正常搜索结果来自同一页面，不能只靠 DNS 域名拦截。模组通过响应脚本
注入窄范围 CSS 选择器隐藏已识别广告容器。YouTube 的视频与广告可能共用媒体域名，
因此模组不封锁 `googlevideo.com`，而是拒绝明确广告路径并保守删除播放器 JSON 中的
已知广告字段和信息流广告渲染器。这些页面结构与接口会变化，不保证永久或完整去除。
X 响应清理曾因空推广字段和 MITM 兼容问题影响正常帖子加载，因此已从正式模组停用。

## App 开屏广告与追踪器

App 广告与追踪器清单只生成 `DOMAIN` 或 `DOMAIN-SUFFIX` 的 `REJECT` 规则，不生成
跳转，不把原始请求发送到拦截页，也不要求对这些域名进行 MITM。腾讯规则优先使用
精确主机，避免封锁整个 `qq.com`、`e.qq.com`、`gdt.qq.com` 或 `gtimg.com`。
QQ 音乐、京东和墨迹天气专项清单同样只使用精确 `DOMAIN`；即使主机名包含
`api`、`cdn` 或 `policy`，也不会扩大为第一方根域后缀。精确匹配降低影响范围，
但不能证明该主机只承载广告，出现功能异常时仍需白名单。QQ 音乐补充清单中的
全民 K 歌、酷狗、酷我和腾讯通用遥测主机也遵循相同限制。

2026-07-29 双源复核批次使用独立远程 `RULE-SET`，每条都是精确 `DOMAIN`，
不会扩大为后缀匹配。该批不加入 URL Rewrite 或 MITM；输入必须同时精确出现于
HaGeZi Multi Pro 与 StevenBlack，并排除关键第一方、支付、系统服务和 CDN 根域。

中国广告/CDN 增补批次同样只使用精确 `DOMAIN` 和独立远程 `RULE-SET`。候选来自
anti-AD 或 AdRules，优先选择同时命中两者的条目，并排除项目现有覆盖、关键中国平台、
政府与教育域名，以及登录、支付、银行、下载、DNS 和更新主机。域名包含 `cdn` 只作为
候选语义，不是充分证据；双源优先、精确匹配和根域分散用于进一步收窄风险。该批不加入
URL Rewrite 或 MITM，也不将整个 CDN 或平台根域扩大封锁。单源候选的置信度低于双源
候选，出现误报时应优先从单源条目开始排查。

哔哩哔哩专项批次只把广告投放、数据流、日志、广告评分和追踪用途较明确的精确主机
加入静默拒绝，不加入 MITM。B 站的开屏、推荐、搜索、动态、直播和视频广告可能与
正常内容共用主 API，因此域名级规则无法安全覆盖全部广告。本项目不会封锁
`app.bilibili.com`、`api.bilibili.com`、HTTPDNS、视频 CDN、静态资源或小程序
主机。两条单源 experimental 规则可能影响国际站数据或聊天功能，实机异常时应优先
逐条放行它们。

规则只能覆盖走系统代理且使用清单域名的请求。使用证书固定、自带 QUIC、硬编码 IP、
服务端合成或与正常内容共域的广告可能无法拦截。广告 SDK 域名通常同时承载开屏、
信息流和激励视频，因此静默拒绝可能令激励视频奖励不可用。分析、崩溃报告、功能开关
和遥测服务也可能影响站点功能，出现兼容问题时应根据命中日志建立白名单。
YouTube App 若因证书固定拒绝 MITM，可能表现为无法加载视频；此时应停用对应
HTTPS 解密，而不是扩大域名封锁范围。

## 误报处理

正式发布前应提供：

- 独立白名单，且优先级高于拦截清单。
- 每次更新的变更记录。
- 可回滚的版本标签。
- 误报申诉入口。
- 自动测试，确保银行、支付、Apple 系统服务和拦截页域名不会被意外覆盖。

## 清单来源

外部情报源必须同时满足：

- 许可证允许重新分发。
- 有明确维护者和更新时间。
- 可区分广告、诈骗和博彩类别。
- 有误报处理机制或足够透明的证据。
- 导入前经过规范化、去重和人工抽样复核。
